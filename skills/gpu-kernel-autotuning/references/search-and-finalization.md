# 有限池搜索与最终选参

## 1. 锁定目标与合法范围

每个候选绑定目标结构、父版本、真实源码与依赖、编译器、实际入口与命中路径、物理 GPU 及数值和资源契约。记录参数声明值和实际运行值，核查默认值替代、裁剪、缓存选择和后端重选造成的差异。

为实现实际支持的 tile、warp、流水级数、split 和映射选项登记有限池及硬约束。保留共同起点或当前最佳配置。把 workspace、计划和编译缓存的生效条件记录到相同绑定。改变任务所有权、算法或分派规则形成新的 O 候选。T 仅调整冻结入口公开的参数。

| 状态 | 处理 |
|---|---|
| 证明非法 | 记录与资源或契约绑定的判据 |
| 模型未知或越域 | 按登记策略实测探索，预测可给有依据的顺序 |
| 有依据可暂缓 | 当前模型和范围经独立准入后登记风险、审计和撤销 |
| 正确且有效 | 保存原始样本，参与选择 |
| 编译、执行、数值或计时失败 | 分阶段记录原因、收据及已花开销 |
| 待测、暂停或结果不明 | 记录阻塞，在核对实际派发和收据后恢复 |

全池覆盖只在原池的合法项完成相应实测时登记。有限池 Oracle 还需要独立确认已实测的最佳可执行项。

## 2. O 阶段执行与选择

1. 冻结参考、容差、真实计时边界、初始保留配置、搜索机会、选择统计、并列规则和失败政策。
2. 用代表配置冒烟，核对实际命中、参数是否生效、资源、正确性及计时器。用实际物理绑定测选中候选而非源码的理论估计。
3. 逐项实测本版的合法配置池或预登记保留项。记录已采及未采，实际缓存复用需匹配源码、构建、设备、输入组织、配置及计时缓存政策。
4. 记录 JIT、预热、辅助 kernel、workspace、真实执行、等待和重试。完整调用对两侧采用一致的边界与资源规则，冷/热入口各自记账。
5. 在正确、有效且可比的试验中按登记统计选出配置。并列处理可以根据登记规则保留原参数或优先较少资源的方案。从搜索结果建立独立确认计划。
6. 对选中候选与同目标现用方案，用搜索外的同输入计时块交错配对。按登记的收益、资源和不确定性政策局部接纳，留存回退参数和失败证据。

可复测记录包括目标、代码、实际配置、物理尝试与输入身份、真实命中、资源、参考和原始时延，还需有结果状态与恢复位置。

## 3. T 阶段给统一入口换参

1. 冻结真实源码、算法、分派、guard、后备及参数域。保存统一入口和 O 保留配置表的可调用快照。
2. 逐目标搜索 T 的合法参数。配置共享内存、workspace、编译、同步或其他参数时，登记相关目标和联合试验。
3. 用独立确认块直接配对 **统一入口 + O 保留配置** 与 **同一统一入口 + T 选中配置**。保持同一 T 输入、实际路径语义、设备、计时边界、资源和状态还原规则。
4. 计算明确方向的配对效果 `time_O / time_T`，按登记估计量和区间判断。区间跨门槛、无法比较、退化或资源异常时，按政策保留 O 或补证据。
5. 联合确认真正交付的整套参数及路由。遇到代码或分派需要变更时，再进入受影响的 O 及集成。冻结参数交给独立 A 评估。

此前 O 的原独立分支计时留作开发记录。参数变化的收益由统一入口内的配对确认给出。

## 4. 断点与交接

每个逻辑试验维护原池、进度与收据。恢复时跳过具有经校验终态的工作。可证明派发前被拒绝的项继续原逻辑绑定。结果不明时先核对执行。重试写新物理尝试并保留旧成本。环境改变时重新绑定受影响基线与配置。

输出包括原池及状态、选中或保留的实际配置、独立配对证据、联合检查、搜索覆盖和已知耗时。统计验收使用本课题单独登记的测量规则。
