# 特化实现与统一分派

本手册用于从一个可运行的共同入口出发，针对已知几何、变长结构或稀疏结构修改 GPU kernel。主模型负责设定目标、选择实验、核对测量和接纳。子 agent 可独立研究、分析或实现不同候选，交付可审查的补丁和证据。

## 1. 选出值得特化的结构

1. **跑通共同起点。** 先确认原分支、本目标配置与输出。起点可调时先实测一批合法配置，独立确认保留配置。采样覆盖典型、困难与规则近邻。
2. **把现象与结构联系起来。** 比较等工作量或等几何的受控输入。记录随长度、空组、对齐、稀疏度、页局部性和排布改变的实际工作、CTA 分布与完整入口时延。
3. **定位限制。** 查源代码计划的工作，独立核对编译资源与实际时序。优先验证一种可区分的现象，例如“空 CTA 太多”和“有效 CTA 大小失衡”需要不同的诊断。
4. **估计实用价值。** 用命中频率、预期每次节省和需新增的分派、元数据、编译、缓存、workspace及维护成本决定优先级。高频微小任务重点考察完整入口。低频任务重点考察是否有可摊销收益。
5. **给出先行范围。** 选定一批明确可能获益的合法结构，加上边界、反例和当前表现良好的结构。范围可以先限于单一精确结构。

| 目标卡 | 需要记录 |
|---|---|
| 问题和对照 | 契约、输入结构、设备、原入口及配置、基线时延、正常与困难用例 |
| 假设 | 实际命中的阶段、瓶颈证据、竞争解释、能推翻假设的观测 |
| 路线 | 变换、实际影响阶段、资源、额外开销、合法参数域和搜索政策 |
| 守卫 | 可运行时取到的字段、合法域、候选适用子域、优先级与后备 |
| 验证 | 独立参考、搜索块、确认块、实际收益判据、受影响目标与回退条件 |

## 2. 区分准确身份、检索特征与分派条件

| 对象 | 做法 |
|---|---|
| 结构身份 | 由契约、外层维度及有序 lengths、offsets、页或稀疏索引等必要结构定义。保存可以重建的数据。 |
| 近似特征 | 总量、活跃组、最长组、偏斜、尾块率、对齐及局部性，帮助挑选候选或设定范围。 |
| 执行条件 | dtype、输出要求、布局、stride、对齐、当前 GPU、索引与资源上界。必要条件应体现在 guard 或统一契约检查中。 |
| 数值实例 | 在同一结构下生成的实际张量值，绑定 stage 和种子或内容哈希。守卫允许查看的字段由契约登记。 |

### 精确结构守卫

- 用稳定的结构字段作路由键。摘要可作为查找索引，在可能存在碰撞或可变元数据时核对完整条件或缓存有效性。
- 常量折叠、专用 launch 和预计算仅消费守卫能保证的条件。记录这些约束落在哪段代码。无效条件走契约定义的错误处理，合法未命中走预登记的后备。
- 处理重复边界、空输入、错序元数据、不同 layout 和索引宽度。缓存键覆盖所有影响生成计划、工作量和正确性的条件。元数据更新使对应条目失效。

### 范围守卫

- 先写一个可行域，例如某 dtype、对齐、N/K 集合及受限的分组长度，再验证域内低中高位、边界两侧、资源极值和典型反例。依据边界证据缩小或扩展范围。
- 需要展平、分桶、重排或设备回读时确认来源与时机。在重用场景分别记录首次构建、缓存命中和每次重新生成的成本。
- 明确精确匹配、范围分支和通用后备的优先级。测试重叠覆盖和路由遮蔽。若某分支较快但 guard 优先级导致从不命中，集成验收需识别实际路由。

## 3. 按限制挑选实现机制

| 现场证据 | 首批备选 | 需要一起核对 |
|---|---|---|
| 计算单元利用不足，尾块浪费或粒度大 | 调整 tile、映射和矩阵指令形状，按小任务切分或有条件 split-K | 有效工作、精度、归约、占用及完整入口的变化 |
| HBM、缓存或访问合并限制 | 比较连续向量读写、布局、数据复用、prefetch、融合或稀疏 gather 组织 | 真实请求与传输、重排或 workspace、缓存与寄存器压力 |
| tile 数少、空 CTA 多或任务尺寸差异大 | 比较按组网格、有效 tile 展平、尺寸分桶、常驻 CTA 或动态队列 | 有效网格、尾波、索引定位、额外 kernel、负载均衡和队列同步 |
| 寄存器或共享内存限制并行、出现 spill | 联合调整 tile、warp、流水深度和中间值生命周期，视情况分阶段 | 资源变化、spill 字节、重算或全局写回和计时 |
| 启动、CPU 准备、辅助阶段主导 | 降低启动数、核内融合、选择可复用元数据、预分配、精简空路径 | 使用实际复用条件测准备、分配、启动数和同步，核对被移入计时外的工作 |

针对每条路线按下面顺序做改动。

1. **写明改动位置。** 例如替换 program ID 到输出 tile 的映射，保持数学计算与累加精度。冻结父代码及其当前最优参数。
2. **说明线程和任务所有权。** 列出每个 CTA 写哪个输出区间、如何处理空任务与尾部、是否存在多 CTA 写同一位置。需要原子操作或合并时登记顺序和数值误差。
3. **明确参数与合法条件。** 为 tile、warp、流水、并行度或 split 因子给有限候选。检查各配置的硬件和契约限制。源码中暴露的参数必须在实际入口中生效。
4. **基于编译证据更新判断。** 复核实际编译选项、生成的执行组织和资源使用。保留必要的编译/运行时失败。建模和剪枝细节见[搜索手册](optimization-and-search.md)。

## 4. 真实的候选矩阵

为每条路线保存父版本及其保留配置作为对照。至少能用矩阵定位“对哪个目标用哪个代码和合法配置验证什么”。

| 行的维度 | 内容 |
|---|---|
| 负载 | 预期命中、边界与退化、合法未命中、原路径较强的对照 |
| 实现方案 | 共同起点、命中分支的已保留实现、不同机制的候选与必要后备 |
| 参数 | 与当前源码摘要绑定的有限池，包含对照配置、编译约束、偏离默认值的理由 |
| 检查 | 独立参考、guard 命中、参数确实生效、多输出/副作用、显存与运行资源、时延范围 |
| 证据用途 | 搜索、独立确认或反例，记录实际派发状态和样本身份 |

先做 CPU 或仅编译检查。对一个小代表批次验证正确性、路径和计时器，对通过代表检查的候选执行真实搜索。每个有资格接纳的源码版本测自己的合法配置。模型只能按已登记范围调整优先级或有证据地暂缓。开展组合优化前用阶段图明确能否叠加并估计相互影响。组合生成新代码时单独重新实调。

## 5. 数值验证、O 接纳与退化处理

- 正确性用独立参考。比较语义要求的每个输出、形状、dtype、容差、输入是否被修改、边界和特殊约束。对可能并发更新的实现重复运行并检查资源的初始化与复用。
- 代表用例覆盖最小非空、整 tile、尾块、空组、相邻守卫上下界、长尾、合法最大值、结构顺序变化。对测试失败保存输入、配置与误差位置，明确编译、运行、数值及资源失败。
- 从同一目标的搜索块选出有效配置，再用独立块配对当前保留版本和候选。采用同一输入、设备和完整计时边界。保存实际路由、workspace、计时及诊断证据。
- 按登记政策在支持范围内接纳。观测暂不确定时保留原实现、继续重复或试其他有根据路线。确认退化时缩小域或回退。记录已覆盖结构及回退、未知、失败和剩余机会。
- 局部有效的结构可以独立保留。对同次改动共享的部分检查所有相关分支，对影响范围不明的更改扩大回归。

## 6. 接入统一入口

```text
检查调用满足算子契约
读取可用的结构与布局元数据
尝试已登记的精确结构分支
按已验证优先级检查范围守卫
取对应的冻结参数和工作区政策
合法未命中则调用后备
登记实际命中路径并交付完整输出
```

集成时加入真实入口的分派开销。核对预期命中、范围外输入、overlap 优先级、定义允许的空输入、缓存失效和共享依赖。验证合法后备的实际时延。把接入前后的完整入口在同一输入和相同参数政策下配对复测。按已登记的回归规则缩小 guard、撤回接入或保留新入口，再冻结 T。A 范围、后备命中和未写特化的目标全部保留。T/A 的冻结、配对和接受证据见[计时与验收](acceptance-and-cost.md)。

## 7. 用一个完整算例串起各阶段

阅读 [MoE Grouped GEMM 特化算例](worked-grouped-gemm.md)。算例包括同 M/N/K 不同分配的推导、候选矩阵、任务到输出的映射、O 接纳、统一入口 T 和独立 A。其他算子依相同过程重写自己的约束与阶段图。
