# 工作负载与基线

## 先锁定贡献和算子契约

- 写清要验证的贡献。按已知结构生成专用实现时，结构可以在优化阶段可见，另保留独立验收的数值实例。要验证未知结构的分派或代码迁移时，单独留出结构或来源实体。
- 固定输入输出、布局、索引和 mask 语义、精度与累加、合法资源范围、同步边界以及前后处理。登记每个算子或几何范围的独立参考和容差。空组、尾块、重复索引等边界要服从契约。
- 准备完整入口可执行的共同起点和按项目选择的强基线。将编译模式、库与后端版本、分配及工作区政策、设备身份和测量政策写入依据。

## 构建结构集合

1. 预先登记生产或公开数据来源、合成参数域、压力机制、样本配额和分层依据。配额按研究问题和资源确定。
2. 导入真实来源及谱系。由真实长度、路由或索引生成随机张量时标为真实结构回放。公开 benchmark 的形状单列来源。
3. 生成可控结构。固定总工作量、精度或矩阵几何，逐项改变需要识别的因素。例如在 MoE 中固定总 token、expert 数及 N/K，改变每个 expert 的 token 数、空组比例或任务顺序。
4. 从实际结构统计覆盖并去重。换数值 seed 保留同一结构身份。把同源派生、成对样本和来源级留出绑定到谱系。
5. 验证合法性、可重建性、参考和后端入口。分别记录非法、超限、参考失败和后端不支持。合法困难项进入预先定义的后备或失败流程。
6. 用有界的构建期反馈补齐覆盖，记录每次尝试。冻结最终结构、权重和分母。总数已够且覆盖或执行能力不足时保留构建未完成状态。

## O、T、A 的隔离

对已知结构优化，为同一结构绑定不同阶段的数值实例或测量块。O 用于实现选择，T 用于完整入口选参，A 用于独立验收。登记每阶段可见性，验收实例、参考和结果由独立评估流程管理。训练、成本校准、风险政策选择和独立验证也按来源或结构分开。

## 做可解释的基线

| 基线角色 | 记录与用法 |
|---|---|
| 数学参考 | 验证当前契约的输出、误差和边界。若兼任性能基线，另登记其真实完整调用。 |
| 高性能库默认 | 走同一语义、高性能后端的正常默认配置。保存后端、返回值和真实计时路径。 |
| 高性能库已调参 | 库提供受支持的 tactic 或配置时，登记原合法池、逐目标测量并独立确认。报告哪些负载保留了默认配置。 |
| 固定实现与同实现调参 | 固定代码框架，比较预设参数与实际参数搜索的收益。 |
| 有限池 Oracle | 完整检查指定的原候选池和全部合法项，记录独立复测及完整搜索成本。 |

配对比较的各方使用同一结构、数值输入、物理设备、计时范围、精度和同步要求。完整入口纳入实际需要的分派、计划、转换、分配、workspace、启动和归并。设备 kernel 或 Graph 计时可以另报，注明对应的成本范围。
