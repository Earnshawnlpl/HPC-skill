# 执行、子 agent 与实验收据

## 1. 运行模式和权限

| 模式 | 本次交付 |
|---|---|
| 设计 | 契约、覆盖、模型与实测设计、比较组、验收政策和已有能力 |
| 实现 | 接通参考、基线、候选与测量入口，提供 CPU 可核查的验证结果 |
| 实测 | 在授权设备和范围内取得原始收据，完成可执行的验证并报告缺失项 |
| 审计 | 追溯版本与输入，核对实际进度、失败、搜索覆盖和完整对照 |

按项目已确认的资源与操作范围推进。仅开放设计时，交付实验矩阵、验证计划和待定政策，实际设备操作及付费模型请求留待授权。准备实验前设置新课题的数据、缓存、临时目录和命名空间，验证写入以及工具、设备和基线能力。按工程或正式的登记身份归档。时间、token、轮次、采集深度、停止条件由当前项目设定。

## 2. 一个模型组织工作

主模型决定目标、机制实验、版本接受、GPU 配对执行和阶段转换。可以由同一模型配置的子 agent 并行查来源、核对工作描述、为独立路线写补丁或审阅边界。主模型也可以顺序执行这些工作。

每份委派给出目标及父版本、可读证据、可改文件、允许的工具、交付结构和完成条件。隔离候选修改，统一保存可审查补丁。把本组的输入与允许反馈放进小型资料包。A 的数值、参考答案和结果由独立评估步骤持有。子 agent 提供分析与候选，主模型核对源码、编译、测量和收据，再合入或回退。

## 3. 阶段交接与记录

通用键为实验、阶段、方法、目标和版本。用稳定格式或摘要记录环境和可重建引用，固定后在其绑定下追加历史。已有记录的语义和时间保持可审计。物理尝试另带唯一 ID，区分逻辑工作状态与设备实际派发。

| 阶段 | 交接所需证据 |
|---|---|
| 负载冻结 | 契约、结构标识及重建、来源谱系、数值实例分配、合法性、覆盖、参考与基线、权重与分母 |
| 基线与建模 | 真实后端和配置、编译与环境摘要、检查、计时政策与原始收据、模型支持范围及验证身份 |
| 候选 | 父版本、目标、实际源码和依赖摘要、守卫、原始有限池、预期机制、前后处理和后备 |
| O 完成 | 配置试验、选中理由、独立配对及正确性、局部守卫范围、失效和剩余机会 |
| 完整入口 T | 分派、后备、影响面、冻结算法、逐目标实调和同入口对照、联合确认 |
| A 与报告 | 各方法已冻结版本、独立输入、实际路径、逐样本证据和逐负载结果、失败及成本 |

记录一次测量可以使用这类内容。字段和值由项目的真实接口提供。

```yaml
run_id: example
stage: O-confirm
method_id: tuned-specialization
target_id: ordered-structure
candidate_id: source-and-dependencies-digest
configuration_id: frozen-or-selected-ID
input_instance: reference-to-versioned-generator-or-snapshot
device_and_environment: reference-to-registered-physical-environment
timing_scope: complete-entry
measurement_attempt_id: independently-assigned
status: pending
evidence: []
```

## 4. 最小可运行链路

先接通“一个合法代表输入、一个独立参考、共同起点和真实基线”，取得可复核的输出和一个实际计时收据。再加候选、有限池和批量调度。测试冒烟至少验证真实调用参数生效，确实命中预期路径，计时器覆盖工作以及输入可重建。

| 环境 | 最小入口 |
|---|---|
| Python 框架或 JIT | 实现接收 inputs 与 configuration 的可调用入口。准备数值及参考，按政策编译和预热，调用、同步及采集原始样本 |
| 原生 GPU 程序或扩展 | 用同一可验证驱动加载不同二进制或入口，显式处理流、布局、workspace 和同步，记录可复现编译选项 |
| 暂无可用 GPU 或入口 | 做 CPU 参数、结构和参考检查，补最小执行适配。实际性能行留待取得设备收据 |

完整入口采用主机单调时钟和对称同步。设备段使用同样的设备事件与流依赖，分开记录设备时延。具体做法见[计时与验收](acceptance-and-cost.md)。

## 5. 共享设备与就绪批次

1. 在 CPU 准备输入、参考、代码、合法配置、批次及可续跑边界。LLM 思考、数据准备、CPU 编译和日志分析期间使用实际所需资源。
2. 优先复用已批准且覆盖本次工作的新课题作业或预约。待真实测量就绪后才登记用途、物理设备和估计占卡时长，按可安全退出的段落拆批。
3. 进入设备队列，按项目规则等待，取得设备锁后复核预约、物理设备和占用。测量配对绑定相同的真实设备，允许的设备组和迁移条件单列。
4. 逐项保存收据。确认异步工作完成、退出持有设备的进程并释放本批预约。在批次末尾留出同步、收据写入和退出时间。

仓库内接入说明见 [GPU 资源登记](../../gpu-resource-scheduling/SKILL.md)。若使用集群原生调度器，记录作业、资源及测量之间的对应关系。

## 6. 恢复、故障和汇报

| 状态 | 下一步 |
|---|---|
| 可证实的派发前拒绝 | 保存判据。条件满足后从同一逻辑工作恢复 |
| 编译或数值失败 | 留下输入、版本、配置与失败证据。修复后重绑版本，或测已登记的替代项 |
| 计时失败或外部干扰 | 用登记政策处理配对块。保留旧尝试，许可重测时生成新的物理尝试 |
| 执行结果不明 | 核对实际进程、设备锁、派发与收据，确认后再恢复 |
| 环境变化 | 建立新绑定，对受影响的基线、资源和性能证据补验 |
| A 中失败或缺证据 | 保留分母和失败原因。依该结果修订时新建开发身份与独立验收 |

保存并校验终态收据后推进逻辑状态。续跑跳过有完整终态证据的工作。报告带时间观测点，分别描述完成数、等待原因、设备测量、有效证据和仍需验证事项。总墙时延续原始起点。成本和交付见[实验成本](ablation-and-cost.md)。
