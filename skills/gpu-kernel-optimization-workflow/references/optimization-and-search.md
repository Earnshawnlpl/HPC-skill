# 分支成本、经验与实际搜索

## 1. 将候选写成可检验的决策

先取共同起点的正确配置、原始计时和必要的资源或 Profile 证据。一张实验计划卡记录：

- 目标契约和结构、父版本、设备、计时范围、当前最优及其选择依据。
- 优先瓶颈、至少一个竞争解释，适合区分解释的指标。
- 每条机制的变换、可能增加的准备或内存开销、约束边界和反例。
- 原始有限配置池、排除依据、搜索机会、独立确认对象、预先登记的接纳政策。
- 产物、候选优先顺序、当前证据与待测部分，区分静态判断、预测和实测。

[特化实现手册](shape-specialization.md)说明如何落实结构守卫和单核修改。改变实际代码后，重新核对工作图、合法池和环境，即使目标结构、函数名和父模型版本相同。

## 2. 构造受信的分支描述与共享成本

绑定结构、分支源码和依赖摘要、编译配置、设备与驱动、计时范围、模型/校准版本。分析当前输入实际命中的分支，包括触发的 guard、前置准备、GPU 工作、辅助阶段和后备。

| 项 | 描述和验证 |
|---|---|
| 计算 | 实际生产的输出 tile、每任务循环与指令类型、有用运算和 padding、特殊数学单元使用与已验证吞吐条件 |
| 访存 | 分开记录逻辑字节、CTA 请求与观测传输。记录地址模式、复用及向量化、对齐和缓存层对应证据 |
| 资源约束 | 用当前编译产物取寄存器、共享内存、线程与 spill。资源约束作用于可行性、驻留与流量 |
| 调度尾部 | CTA 数、任务尺寸分布、wave、空任务、最长任务和运行轨迹能支持的负载均衡信息 |
| 组合 | 增加真实的索引生成、启动、分配、workspace、归约、同步与主机服务。把共享服务计入一次，按依赖及有证据的重叠计算 |

同一组硬件组件可以服务多个实现。每个候选独立生成工作和依赖。编译得到的驻留上界和反事实成本预测标出假设。缺少层级或形态证据时保留部分支持或未知。

| 时点 | 可用证据 | 用途 |
|---|---|---|
| 源码分析或仅编译之后 | 输入、源码、可独立核对的构建元数据 | 未执行分支预测、合法性与搜索顺序 |
| 真实执行之后 | 当前分支、配置和输入的计时与采集器输出 | 解释观测、复核预测、形成新的候选假设 |

## 3. 组件校准与覆盖验证

1. 在允许的物理环境中，用可复现微基准控制 dtype、访存形态、工作量、网格和资源，测量所需组件。独立记录编译、预热、冷/热和物理执行边界。
2. 给每个服务登记输入特征、单位、有效域、测量来源、保留误差和适合的组合规则。同一入口里的重叠用证据校验。
3. 在独立的工作形态和配置上验证预测误差、不确定性覆盖和排序决策。若仅有已知源码的结构验证，结论限制在此分析域。修改模型、校准或计时政策时重新绑定受影响证据。
4. 候选实际测量前冻结预测及选择依据。超域和未知结果保留探索资格。GPU kernel 或 Graph 成本在相应计时范围内使用。
5. 用真实配对结果复盘哪些观测足以解释瓶颈。将可迁移的机制和反例写入版本化经验快照。

## 4. 维护可败证的经验库

每条经验保留来源、版本/许可证、已验证契约、结构特征、机制、源码与配置域、独立复测、失败与开销。记录后续每次检索实际使用了哪个快照、选中理由与边界。精确匹配的源码仍针对目标重新调参、检查正确性并确认完整调用。跨算子迁移主要保存机制与假设，重新获得新目标的运行证据。

同一方法内可以在目标之间复用已经登记的证据。对照方法的公共输入材料在实验前固定。本地优化结果按可见性留在对应方法和阶段。

## 5. 实测搜索、准入、审计

| 状态 | 处置 |
|---|---|
| 已证明非法 | 记录与精确配置绑定的硬约束及依据 |
| 合法且保留 | 做对应版本的真实正确性和计时，记录编译及失败 |
| 模型未知或超域 | 进入登记的探索策略。模型输出仅可提供有依据的优先级 |
| 有证据可暂缓 | 仅在当前模型、设备、目标成本域和风险政策均通过准入时应用。保存判断、审计与撤销条件 |
| 未完成或结果不明 | 明确原因和恢复身份，在可核对后继续 |

准入登记风险指标、置信校准、独立验证、保留/探索、审计采样、撤销规则和代价。保守暂缓需要能证实本范围内候选的乐观成本也达不到登记收益目标，且计入合法域和不确定性。整条路线的暂缓覆盖原合法池，否则仅针对已有证据的配置。

用完整的登记池保留搜索可追溯性。先影子审计拟剪项，再按策略做实际搜索对照。若观测推翻暂缓前提，重新打开受影响项，并保留新旧选择与成本。记录按政策完成、全池穷尽、实际派发、拟剪/实际少测、错误以及证据不确定的不同状态。

## 6. 选中、复测及下一轮

每版候选实调后从正确且有效计时的配置里选出候选。以独立交错样本和该目标的当前保留版本做完整入口对照。按事先登记的正确性、实际收益、资源与维护政策局部接纳、保留或回退。只在全部配置的穷尽证据齐全时报告有限池 Oracle。

判断是否继续时检查剩余机制与已验证约束。一次失败可以缩小路线，其余结构或机制照常验证。若到达停止条件，保存最后一份可运行配置、未决项和对应的后备。T 只搜索已冻结实现所声明的参数域，实际算法或分派变更重新进入 O 验证。
