# 算例：用结构控制优化 MoE Grouped GEMM

此处的尺寸和配置是用于说明流程的算例。真实实验的 dtype、精度、范围、合法池、采样和收益政策从本课题登记。

## 1. 确定输入及参照

固定 `M=128, E=4, N=512, K=256`。每个 expert 保持自己的权重 `W[e]`，按有序 offsets 把连续输入行交给对应 expert，返回原行序的输出。固定累加、输出 dtype 和空组语义。

| 结构 | 每 expert 的行数 | 有序 offsets | 用途 |
|---|---|---|---|
| U | `[32, 32, 32, 32]` | `[0, 32, 64, 96, 128]` | 分配均匀的对照 |
| S | `[112, 16, 0, 0]` | `[0, 112, 128, 128, 128]` | 长尾与空组 |
| P | `[0, 16, 0, 112]` | `[0, 0, 16, 16, 128]` | 与 S 具有相同无序摘要的顺序反例 |

独立参考按每个非空 expert 的输入切片直接做矩阵乘法，把输出写回原行号。测试侦测错误 expert 映射时，给各 expert 使用不同的权重。另用同契约参考检查精度、尾块和特殊值。

## 2. 形成可检验解释

假设共同实现按最大 expert 长度构造矩形网格。设参数 `BM=32, BN=128`，则 N 方向有 4 个 tile。下列是按该映射计算的任务数，用于设计验证。

| 指标 | U | S、P |
|---|---:|---:|
| 网格排出的 CTA | `4 × ceil(32/32) × 4 = 16` | `4 × ceil(112/32) × 4 = 64` |
| 具有有效输出的 CTA | `4 × 1 × 4 = 16` | `(4 + 1) × 4 = 20` |
| 无输出的 CTA | 0 | 44 |

先核对共同入口实际使用这种网格。假设 S 可能因空 CTA 和尾波付出开销。竞争解释是时间主要花在有效 tile 的读写或 GEMM 指令，展平会引入索引成本。采同一目标、配置的完整入口计时。工具可用时补采实际网格、每 CTA 工作量、尾部、访存与编译资源。保留原始时间和观测。

## 3. 候选及参数设计

| 路线 | 代码与候选配置 | 要验证的判断 |
|---|---|---|
| R0 分组矩形网格 | 保留原映射，用登记的有限池实调并确认 | 提供正确完整入口和保留参数 |
| R1 展平有效 tile | 由输入 offsets 计算各组有效 tile 前缀，只派有效 task。比较资源允许的不同 BM/BN、warp 和流水组合 | 减少空任务的收益是否覆盖任务定位及前缀准备 |
| R2 分桶或常驻 CTA | 有确认的调度尾部时再加入。按组长度组织，或让 CTA 从固定任务表领取更多工作 | 额外队列、分桶、同步与资源是否划算 |

每条路线的描述包括源代码实现、合法的有限池与不合法理由、哪类输入预计获益、真实开销范围和反例。参数域应由具体实现与架构给出。一次只改一个可诊断的机制，组合路线独立计时。

### 执行矩阵示例

| 顺序 | 结构与路线 | 记录及下一步 |
|---|---|---|
| 起点 | U、S、P × R0 | 实调并独立确认各自起点，记录已确认配置及实测边界 |
| 首轮候选 | S × R1 | 填任务描述、原有限池、编译和各配置收据。用独立 O 确认块配对 R0，决定是否为 S 接入 |
| 适用域反例 | U、P × R1 | 复用机制并为 U、P 各自合法实测。用配对证据决定是否覆盖顺序和分布变化 |
| 条件候选 | S × R2 | 确认有尾波或负载不平衡证据后开始，保存触发观测，单独实调并复测 |
| 集成确认 | U、S、P 与合法未命中输入 | 记录命中和后备。用相同输入与参数政策配对变更前后的完整入口 |

每行继续记录阶段、结构键、源码与配置标识、数值实例、实际路径、正确性、原始时延和决定。下一动作由本行结果和登记的停止政策决定。

### 展平映射落实到代码

```text
tiles_m[e] = ceil(length[e] / BM)
tiles_n = ceil(N / BN)
prefix[e+1] = prefix[e] + tiles_m[e] * tiles_n
launch prefix[E] 个 task
e = upper_bound(prefix, task) - 1
offset = task - prefix[e]
tile_m, tile_n = divmod(offset, tiles_n)
row_base = m_indptr[e] + tile_m * BM
以 expert 的非空域、N 和 K 的边界分别构造读写 mask
使用 W[e] 计算并写回同一 expert 的原始输出行
```

`upper_bound` 的使用要覆盖 repeated offsets 与 prefix 重复值。测试首尾空组、全部空、部分 tile、不同组顺序和跨整数边界的索引。逐 task 的写区域不能重叠，除非显式使用并验证了归约。对全空输入走合法的空入口。若 prefix 位于 CPU，核对与 GPU offsets 的一致性及取得方式。前缀生成和传输计入实际路径。

## 4. 从 O 到统一分派

1. 为 U、S 和 P 分别绑定起点、候选与资源。跑完合法池实际正确性和搜索，使用独立样本把各目标上的候选与该目标保留配置配对。把 R1 的额外前处理纳入统一口径。
2. 如果 R1 在 S 稳定改善，就先给 S 加精确 offsets 守卫。在 U 及 P 各自依据实测决定路径。空组数相同也要验证其真实排列。
3. 在统一入口回归。确认 S 命中 R1、未登记结构走后备，U 不被遮蔽，P 只有在其守卫覆盖时才命中。测试数值变化、近边界、缓存失效、持续输入变化和真实分派开销。
4. 若想给一类长尾任务共用 R1，先根据能够低成本得到的特征定义范围。到新形状、有序排列、边界和设备资源族上测试，保存域内反例与回退理由。
5. 冻结新入口的算法及分派后做 T。对 S 在同入口和同批 T 输入上配对旧 O 参数与新 T 参数。按登记政策决定留用，最后联合确认所有路由与参数。
6. 冻结并用独立 A 比较真实强基线。保留每个结构的实际路径、收益、失败和后备。验证未见结构泛化时使用另行登记的结构集合，并照实报告 fallback 覆盖。

最终交付包含契约、结构和数值清单、真实基线、全部候选与状态、精确或范围守卫、统一入口、已冻结配置、A 数据和完整成本。分析结果示例只来自实际收据。
