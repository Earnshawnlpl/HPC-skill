# GPU Kernel 优化工作流

为一个新课题建立可复测的优化流程。使用**一个主模型**负责工作负载设计、证据分析、实现决策、调参和验收。可由同一模型配置的子 agent 分担独立任务，主模型负责汇合证据并决定接纳或回退。

## 先确定任务范围

- 设计任务交付契约、实验组、负载与验收方案。实现任务先接通参考、基线、候选和测量流程。实测任务遵循本项目已授权的资源、预算和数据目录。
- 登记算子语义、完整入口、支持的结构域、参考、基线、物理设备、环境、计时范围、容差、收益判据与允许的试验。区分已知结构特化和未见结构泛化。
- 初始化新课题自己的运行目录、经验库和校准身份。复用源码或机制时记录来源版本、许可证和适用条件，在新目标上重新验证。
- 一项关键能力或政策缺失时，标记受影响的阶段，推进独立的设计、CPU 验证或证据整理。按实际完成的阶段交付。

## 从工作负载到独立验收

| 阶段 | 工作与退出条件 |
|---|---|
| 契约与负载 | 导入真实结构，生成可控配对和压力样本。核验数学参考、重建、覆盖和资源后，冻结结构、权重、共同起点和阶段实例。 |
| 基线与建模 | 先验证并测量实际基线。按任务需要独立校准共享硬件组件，提取当前目标实际命中的分支执行图，结合计时和必要 Profile 提出可检验的优化假设。 |
| O 代码优化 | 选择机制，提交带父版本的候选。通过正确性后实际调参，用独立配对样本测完整入口，按登记政策局部接纳、保留或继续试验。 |
| 集成与 T | 将已接纳分支接入统一入口，核对守卫、后备和受影响输入。冻结算法和分派，再实调允许参数，复测并确认整套配置。 |
| A 独立验收 | 冻结唯一提交入口和配置。用隔离数值实例，在相同计时边界内完成正确性、基线和消融的配对比较，归档全部结果与成本。 |

- 设计负载、共同起点和强基线时读[负载与基线](references/workload-and-baselines.md)。
- 检索经验、分析分支成本、调度子 agent、做实际搜索或剪枝时读[优化与搜索](references/optimization-and-search.md)。
- 执行 T/A、设计消融、报告耗时与用量时读[验收与成本](references/acceptance-and-cost.md)。

## 执行与恢复

- 主模型维护唯一实验账本和阶段状态。可以并行审阅来源、诊断或实现彼此独立的候选。候选交付包含目标、父版本、补丁、合法配置与验证建议，主模型核验并合入。
- GPU 批次先完成 CPU 准备，待测任务就绪后按预计占卡时间预约。在设备锁内核对物理设备和占用，测量完成后同步、保存收据并退出，随后释放预约。共享设备按部署的排队规则执行。仓库内的 [GPU 资源登记 Skill](../gpu-resource-scheduling/SKILL.md)可用于支持的部署。
- 以目标、阶段、源码、实际配置和物理测量身份保存收据。恢复时校验已冻结身份并跳过已有终态收据的工作。可信的派发前拒绝可以续做，派发结果不明确时先核对收据。
- 结果分别记录流程进度、正确性、性能、搜索覆盖、剪枝适用范围及成本。把所有登记目标留在分母里，标记失效、未测、超域及后备命中。
