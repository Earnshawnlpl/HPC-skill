# 专家经验卡与可验证复用

## 卡片最小字段

| 字段 | 记录要求 |
|---|---|
| 来源 | 原始论文、代码版本或可重建收据，许可证、代码摘取范围与依赖 |
| 作用 | 哪个结构、实际执行阶段与限制触发机制 |
| 实现 | 修改哪里、并行与数据组织、需要的前后处理和合法参数 |
| 守卫 | 有序结构、dtype、layout、资源和复用条件，列出域内检查及合法反例 |
| 证据 | 绑定源码、确切参数、参考、观测、配对结果和使用的计时范围 |
| 代价与失败 | 分派、建表、融合、workspace、缓存或精度风险，记录发现的不适用区域 |
| 版本及可见性 | 作用域和状态、公共或方法局部、新增和废弃关系 |

根据已获得的证据在卡片上标记假设、静态复核、仅编译、实际正确、独立实测与可复用。保留题设、原始值和权衡。真实证据支持局部结论时可以建设窄范围记录。

## 检索与验证

1. 从目标结构提取在运行时可取的特征。把精确结构键、用于相似性检索的描述和实际守卫分别登记。明确查的是否相同算子契约、阶段和计时范围。
2. 优先选择机制最相关、证据和维护情况可核对、复用条件能在当前目标验证的卡片。检索没有命中时记录原因，可以转向基线与竞争路线分析。
3. 保留复用原实现、适配变换或新写候选的决定。对新输入绑定当前源码与参数、重新核对环境及 guards，按当前目标做正确性、真实调参和独立确认。
4. 将新观测写回本方法的结果。若要修改共享机制，形成新版本并注明可证实的适用范围。评估使用冻结公共快照，独立验收反馈留在评估范围。

## 失败与迁移

按编译资源、数值或路由、速度、实测范围不匹配和证据缺失记录失败。一个失败输入可以是守卫边界或后备必测项。跨算子或设备迁移先取机制及边界，再验证新架构上的组织、实际开销和精度。为经验/检索消融保存共同起点、公共库和各目标是否真正命中的收据。
