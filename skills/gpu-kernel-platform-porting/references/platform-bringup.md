# 平台登记、后端接口与目标机放行

## 1. 确定硬件、软件路径及证据口径

对每种目标组合独立登记芯片型号与架构、可唯一确认的设备身份、运行节点与环境、宿主 ISA 和操作系统、驱动、固件、运行时、编译器、目标 ISA、设备库、翻译或兼容组件、调度权限。版本或目标 ISA 变化时重新核对实际受影响的证据。

| 维度 | 值与证据 |
|---|---|
| 实际执行设备 | 目标设备、CPU、模拟器、未知。用实际运行收据和设备返回值确认 |
| 构建路径 | 原生 SDK、生成目标设备代码的可移植编译后端、版本化兼容层。记录编译命令、目标文件、架构和依赖 |
| 运行路径 | 核函数、库后端或回退的实际调用。用可用的运行时状态、已加载二进制、设备专属队列或跟踪取证 |
| 能力状态 | 支持、不支持、未知。另记文档依据、探针编译结果、实机验证、来源版本与适用域 |
| 结论等级 | 环境登记、编译通过、真实设备探针、通用入口正确、特化正确、同边界性能。各等级保留所需收据 |

原生 SDK、可移植编译和兼容运行都可以成为已验证目标机路径。标清实际依赖和生成的目标代码。框架前端设备名称、编译成功、CPU 参考和仿真结果各有自己的验证范围。

## 2. 分开可复用语义与目标设备实现

| 层 | 应复用和应检查的内容 |
|---|---|
| 数学契约和参考 | 数值、输出与不可改变的布局/索引语义，独立参考、误差政策与可重建测试 |
| 可移植工作描述 | 有序结构键、任务所有权、边界、合理的前后处理。保留每个目标配置的真实任务数和资源假设 |
| 后端适配 | 平台的编译及部署、能力查询、内存/布局、任务与同步映射、运行时调用、设备计时及基线接口 |
| 专用实现 | 按本机可用的向量、矩阵单元、原语和片上存储表达。每个 guard 和合法配置池在目标机验证 |
| 分派与后备 | 先识别设备及契约，选择能力、资源和结构同时满足的分支。合法未命中走已验证的同语义路径 |

建议给后端提供可替换的能力查询、编译、调用、同步、计时与后备入口。这些职责由项目的真实 SDK 或框架实现。调用收据记后端、包版本、代码摘要、配置及分派路径。缓存键至少包含影响有效性的设备架构、构建、精度、真实配置与有序结构。

## 3. 能力矩阵要逐个验证

| 类别 | 检查内容 |
|---|---|
| 精度和运算 | 读写和累加类型、舍入/特殊值、向量、矩阵/张量单元、准确归约和所需原子操作 |
| 任务与同步 | 目标设备的任务单位、subgroup 或适用并行原语、barrier、流/队列和内存可见性 |
| 存储和资源 | 对齐、索引宽度、全局及片上存储、workspace、占用约束、编译后的寄存器和溢出证据 |
| 工具与运行 | 编译目标与真实加载、设备身份、kernel/图/同步计时、可用 profiler 和库后端 |

给每一项写“此分支必须、可选加速或无需使用”。探针覆盖实际类型、指令和形态。矩阵指令或固定 subgroup 宽度未知时，先使用已验证的通用向量、SIMD 或标量设备路径。需要原语但不可用时，改用具有相同语义的分段处理或归并，并复核额外开销。契约所需的能力无法表达时保留不支持状态。

## 4. 从环境到实机验收的凭据

1. **P0 准备。** 先识别已经部署的作业环境和设备权限。依据目标型号官方样例取得匹配的 SDK 与库，冻结版本和重建命令。需要改系统驱动、安装组件或使用付费资源时遵循项目授权，优先使用已批准环境。
2. **P1 最小设备探针。** 在目标计算节点跑通分配、输入传输、生成或加载实际目标代码、提交流、同步和读取输出。用一小组非平凡已知值检测目标机计算。保存设备选择、真实运行路径、编译/运行日志和参考校验。CPU 参考可用于核对，device 路径应能独立确认。仅编译环境保存构建条件及权限缺口。
3. **P2 通用实现。** 从项目实际完整入口调用目标原生实现、经验证的可移植后端或兼容层。测试正常、空、尾部、布局和资源边界。接通当地实用的真实强基线及共同起点，锁定默认与可调路径、时钟和工作区规则。库无匹配算子时，报告可核验的本机通用对照及比较缺口。
4. **P3 特化。** 在本机能力域重建合法池和守卫。以本机已验证保留项作对照。逐版本编译、校验、实测搜索和独立 O 确认。明确元数据预处理、后备与完整开销。
5. **P4 集成与 T。** 用目标机的统一入口检查实际路径、fallback 和交叉影响，按登记规则调整真实参数。使用同一完整入口及输入配对 O 保留参数和 T 选中参数。联合确认后冻结一个本平台的可执行提交。
6. **P5 A 与交付。** 使用独立输入同卡配对确认真实基线、候选和后备。交付精确版本、构建/运行方式、实际覆盖、逐目标正确性、时延和配对不确定性。未触达门槛和缺失证据如实纳入登记分母。

## 5. 性能证据按平台重建

源架构可以提供结构、机制和瓶颈假设。每个目标重新检查寄存器或本地存储、编译器设置、合法参数、实际始末计时、冷/热复用状态和硬件成本支持域。模型移植后在本机做独立校准及风险验证，再考虑启用剪枝。

在目标机测量完整调用与当地可比基线。设备事件或可用计时器单独登记，完整入口记录同步和必要的排布、通信、分配、workspace 及传输。缺关键计数器时先做可靠计时和正确性，计数器结论保持未知。基线和候选结论使用同一物理设备；跨卡结果分别给出版本、边界与可比范围。

## 6. 失败时的下一步

| 观察 | 如何推进 |
|---|---|
| 找不到可访问的设备或匹配 SDK | 先完成契约、静态/CPU 测试和官方能力核对，登记缺少的型号、权限或包 |
| 编译成功但未取得目标机运行证据 | 查编译目标、ABI、库和设备选择。执行可证明目标机实际输出的最小探针 |
| 借用兼容路径才可执行 | 单独记录翻译组件、成本、实际 ISA 与真实设备收据，以该组合做验收 |
| 加速原语或库不支持该结构 | 尝试已有相同语义的通用设备路径或本机原生重写，合法后备真实计时，保留支持缺口 |
| 在目标机不正确或无收益 | 核对数值、索引、工作组/队列顺序、编译资源、布局与时间范围。修复后换版本复测，可退守已验证通用入口 |
| Profiler 或模型失效 | 如有可用时钟，继续正确性和实测。对未知因果与模型准入分别标记 |

每个目标环境成为单独的报告单元。支持范围同时包含环境、输入域、实际后端、能否构建、真实派发、正确性和性能证据。
