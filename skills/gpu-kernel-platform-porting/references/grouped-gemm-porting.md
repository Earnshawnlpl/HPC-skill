# 变长 Grouped GEMM 的跨平台实现示例

本算例展示如何从一个已知可运行的内核出发，为新 GPU 或加速器重新落实逻辑工作、通用实现和特化。目标平台的能力与性能由实际测试填入。

## 1. 固定可移植任务合同

输入以有序 offsets 划分各 expert。第 e 组读自己的切片与对应权重，结果写回原行序。记录输入输出 dtype、累加、布局、合法索引宽度、空组、尾部和 workspace 约定。以独立参考逐组计算。测试中让各 expert 使用不同权重，便于发现路由串位。

使用几何相同但结构不同的三例。

| 结构 | 各 expert 行数 | 预期测试点 |
|---|---|---|
| U | `[32,32,32,32]` | 组长均匀 |
| S | `[112,16,0,0]` | 空组及长尾 |
| P | `[0,16,0,112]` | 与 S 同无序摘要、不同顺序 |

再加完全空、最小非空、部分尾块、对齐边界及合法最大索引。结构相同而数值不同的输入按 O 搜索、确认、T 和 A 分阶段准备。

## 2. 把逻辑任务映射到目标后端

复用数学任务描述。对某个目标后端的合法 tile `BM, BN` 构造：

```text
tiles_n = ceildiv(N, BN)
jobs[e] = ceildiv(length[e], BM) * tiles_n
prefix = checked_prefix_sum(jobs)
for each logical job in [0, prefix[E]):
    expert = upper_bound(prefix, job) - 1
    local_job = job - prefix[expert]
    tile_m, tile_n = divmod(local_job, tiles_n)
    process the owned rectangle using expert's weights
```

前缀计算检查整数上界，测试重复前缀、首尾空组及全空时的零任务。写回范围与参考契约统一。后端决定每个物理工作单位执行一个或多个逻辑任务。SIMT GPU 的线程与 subgroup，向量或矩阵加速器的并行和片上数据组织各自实现。预计算在真实需要时测主机建表、传输和缓存失效。

## 3. 用能力矩阵选初版代码

| 路线 | 前置证据 | 验证 |
|---|---|---|
| G 本机通用入口 | 目标运行时和通用设备计算能力 | 正常、空组、尾块、乱序分布及完整入口对照。可先用本地库或可验证的朴素设备核 |
| V 有效任务展平及向量化 | 当前平台可用的向量、任务映射、对齐或掩码 | 向量条件外保留安全读写或回到 G。检查任务定位和额外建表 |
| M 矩阵或片上流水特化 | 实机证实 dtype、累加、布局、tile 及资源在允许范围内 | 验证计算和掩码、共享/片上存储、同步及新的合法池。只对有资格的结构启用 |

从 G 取本机正确完整入口计时，再比较 V 或 M 的真实候选。用 U、S、P 判断展平或分桶的适用域。保留扩域反例和合法未命中条件。按本机资源选择搜索空间，源架构参数可以提供假设。

## 4. 得到目标平台结论

1. 先获取 P0/P1 凭据，再让 G 通过合同和本机基线校验。
2. 为 V、M 等每版分别登记原参数池，在目标机 O 实测、独立复测及接纳。
3. 用 `backend × contract × ordered structure × capability` 确定实际分派条件。所有合法未命中输入执行已验证后备，实际分派、准备与同步计入统一入口。
4. 核实相同配置政策下接入前后时延。冻结代码和守卫后做本平台 T，配对统一入口中的 O 参数和 T 选中参数并联合验证。
5. 用目标机独立 A 输入对当地基线验收。记录各结构命中、正确性、真实收益和设备约束。报告支持的具体型号、软件栈、契约、尺寸及边界。

CPU 可为任务映射与语义提供辅助检验。真实设备执行、实际配置和可比收益分别有自己的收据。
